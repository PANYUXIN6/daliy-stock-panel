# AI 试运营点数与用量统计

## 规则与账期

游客每月 60 点，Pro 每月 4,000 点；助手每个新问题 3 点，个股、财务、复盘、概念轮动和行业轮动每次生成各 5 点。查看历史报告、打开已有结果不扣点。助手内部取数、模型轮次与自动重试属于同一个任务，不重复扣点。AI 连接测试也使用助手额度。

当前只按点数限制使用：没有单任务金额上限、月度金额上限或故障补偿预算拦截，也不因统计用量而收紧输出参数、思考配置或模型轮次。费用与点数分开记录，不按实际金额追加扣点；点数不足以支付当前入口时，拒绝新任务并提示下月刷新。原有权限、模型服务并发和助手业务流程限制继续适用。

现有账号只保存 Pro 到期日，没有订阅起始时间。因此统一使用北京时间自然月，每月 1 日刷新，不结转。月中升级只把当月总上限提高至 4,000，已用和在途点数保留；续期或修改到期日不重新发放。到期或降级后按当前有效角色计算剩余，最低为零。跨月结束和退款仍结算到任务启动时的月份。

管理员手动通过这些入口生成时记录零点任务和模型用量，不扣游客或 Pro 的点数。现有管理员接口、助手工具和动作确认限制保留，点数不授予额外功能权限。没有绑定用户任务的内部管理员调用及定时任务暂不包含在用户用量中。

## 责任边界

| 模块 | 职责 |
| --- | --- |
| `services/ai_credit_policy.py` | 默认额度、各入口价格、模型报价及可选成本控制参数的类型和校验 |
| `services/ai_credits.py` | SQLite 账本、月度额度、事务预留点数、任务去重、用量记录、批量用户统计、幂等结算和中断恢复 |
| `services/ai_metering.py` | 每次模型请求的 usage 采集、报价匹配和费用估算；默认不干预生成参数 |
| `services/ai_prompt_data.py` | 个股与财务分析的无损表格编码，减少重复字段名；数据来源、单位与取数范围由原分析器保持 |
| `services/ai_credit_stream.py` | HTTP 响应前创建任务，绑定调用上下文，根据完整业务流判定扣点或退款；响应取消兜底 |
| `api/ai_credits.py`、`api/users.py` | 当前账户额度、管理员运行规则和用户列表的当月用量视图 |
| `frontend/src/lib/aiGeneration.ts`、`useAiCredits.ts` | 生成前读取最新价格、任务标识、规则版本、统一刷新余额和按账号共享查询 |

```text
web 验证会话 → collector 验证会话与现有权限 → 事务预留任务点数
  → 绑定任务 → 装配数据 → 逐次请求模型并采集 usage
  → 完整报告归档/助手结束 → 成功确认扣点，失败退点
  → 前端刷新服务端余额；管理员按用户查看月度汇总
```

只有 collector 实际执行并扣点，web 仅转发。`GET /api/ai/credits` 也由 collector 回答。浏览器不自行加减余额，不传可信角色、账号归属或扣点金额。有在途预留点数时共享查询每 2 秒刷新，结算后停止短轮询，避免取消后的查询先于后台结算而长期显示旧余额。未绑定任务的普通用户模型请求会被底层拒绝，新增入口必须显式接入任务包装。

用户管理直接读取共享台账，仅对当前页账号批量聚合。任务点数和模型调用分开分组，避免一次任务的多轮调用重复累计扣点；不需要借用目标用户会话，也不读取其私人文件。用量不会每行独立请求或全盘遍历用户数据。

## 用量与金额口径

用户管理的“本月 AI 用量”展示当月已用／总点数、在途预留点数、模型调用次数、已上报的输入／输出／合计 tokens 和估算金额。失败、取消和重试只要已产生模型调用，就保留其已上报用量；失败退款不会抹掉模型成本。

费用按该任务启动时保存的模型报价计算。目前可估价的目标是官方 DeepSeek Flash 文本接口；输入未命中、缓存命中和输出分别核算，当前默认报价为 2、0.04 和 8 元／百万 tokens。输入／输出 tokens 来自模型实际返回的 usage，输出已包含的思考 tokens 不重复相加。该金额是按配置报价的估算，不是供应商账单对账结果；缓存、折扣及报价变化均可能造成差异。运营核价可参考 [DeepSeek 官方报价说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

- 没有有效 usage：标记未上报，不填零 tokens，也不把过去的费用预留当作实际消耗。
- 已上报 tokens 但没有可用报价：记录 tokens，金额留空并标明未纳入金额；不阻止模型使用。
- 同时存在已知与未知调用：汇总已知部分，并提示缺失调用数；全部金额未知时显示“暂不可估算”。本月没有调用时显示零。
- 流式 usage 可能位于空 `choices` 的尾帧，必须继续读取；多帧累计 usage 取最终值，不重复累加。
- 旧台账可能把最坏预留费用记入 `cost_micros`。迁移后保留原记录并标记 `legacy`，不把它混入已上报金额；有真实 tokens 的历史记录仍可汇总 tokens，并提示缺少可核算报价。

为看清实际请求，任务内关闭 SDK 隐式重试，在适配层保留首包前最多两次网络／限流／服务端异常重试，每次分别记录。已输出的流不会自动重放。兼容接口不支持可选的 `include_usage` 时移除该参数重试，统计缺失不阻止完整回答。

个股与财务提示词将同字段记录编码为 `columns / rows`，字段名只发一次，保留所有值、字段含义与行序；异构记录保持原对象数组，缺失、null 与零不互换。提示词测试的费用样本用于观察体积，不作为运行时金额上限或质量评测。

## 运行规则与以后调整

规则和账本存放在当前环境 `data/auth/ai_credits.sqlite3`；首次运行写入默认规则，部署不覆盖环境规则或其他环境的额度。已有台账以加法迁移补充用量来源字段，保留账号、会话、报告及用户数据。

- `GET /api/ai/credits`：当前账号的账期、重置时间、额度、已用／在途／剩余点数和各入口 `points / available / reason`。默认 `cost_limits_enabled=false`、`cost_limit_cny=null`。
- `GET /api/users`：仅管理员，用户列表附 `ai_usage` 当月汇总；搜索、分页和账号管理权限保持原契约。
- `GET /api/ai/credits/policy`：仅管理员读取完整规则和 `policy_version`。
- `PUT /api/ai/credits/policy`：仅管理员，提交完整 `policy` 和读取时的 `policy_version`；版本冲突返回 409。现有登录与同源校验适用。

额度、入口价格和模型报价集中在规则中，页面及生成路由不硬编码扣点数值。保留可选的 `enforce_cost_limits` 开关及成本参数，当前默认关闭；旧规则没有该字段时也按关闭处理。每点费用、故障预算、额外输出和轮次限制只在显式打开此开关后生效，不会因已有费用或告警记录自行开启。当前没有对单用户金额作上限保证。

每个任务持久化启动时的规则、价格与账期快照，已有任务不受之后调价影响。前端携带 `X-AI-Request-ID` 与 `X-AI-Policy-Version`；若已展示价格与最新预检不一致，先刷新展示并要求重新发起；预检后规则再变则服务端返回 409。按用户和请求 ID 唯一，失败退款后的同 ID 也不重新执行。旧客户端未提供 ID 时服务端分配 ID。

## 结算与失败处理

- 成功：完整结果及归档成功后确认固定扣点，不因实际费用较高追加扣点。
- 系统失败：退回点数；`error` 后即使还有 `done` 也失败，归档失败同样退点。
- 主动停止或网络断连：模型调用开始前退点；开始后保留本任务固定扣点。HTTP 断连无法可靠辨别是否用户主动取消。
- 截断、模型资源中断或缺失完整结束标记：不把部分正文或工具参数当完整成功；已收到的 usage 仍然记录。
- 缺少 usage 或报价：仅影响统计完整性；正常结束的完整回答仍可成功扣点。
- collector 持有唯一执行锁后，启动时将中断任务退点，未知用量保持未知；web 启动不恢复 collector 任务。

# 网页与采集服务拆分开发计划

需求来源：[任务.md](../任务.md)。本任务属于 L3：现有扩展点不能改变核心生命周期、数据读取与执行所有权，因此直接修改相关核心接线，复用现有领域服务、任务记录、Provider、Parquet 与 SSE。已有工作区修改须保留。

## 已确认的实现边界

- `web` 负责认证、页面、本地行情查询与页面推送；`collector` 是唯一供应商访问、调度、实时监控及任务执行所有者。两个进程共享 `DATA_DIR`，各自有独立生命周期。
- 使用已有 `httpx` 在两服务之间转交显式操作和运行中任务状态，保持原 HTTP 路径。批量查询虽然使用 POST，仍是本地读，不能按 HTTP 方法笼统代理。
- 配置、策略、监控及用户数据写入在 collector 中执行，避免两个进程同时修改 preferences。原有 reload 和运行时接线继续在真正执行者中生效。
- collector 保存指数快照与更新状态，web 加载共享结果、刷新相关内存缓存并广播；供应商请求次数不随浏览者数量增加。
- 日历由 collector 更新并保存，查询与时段判断只读本地日历；未知日历明确显示未就绪，不增加工作日猜测、供应商探针串联或自动补齐。
- 常规实时轮询默认 30 秒，北京时间上午 09:30–11:30、下午 13:00–15:00；午休、节假日停止。保留已有收盘快照确认，盘后任务继续。
- 普通分时采集池为自选、启用监控标的和核心四指数，股票／ETF／指数分别存储；浏览动作不扩池。全市场分钟采集仍由原可选能力控制。
- 复盘发布独立于 AI：盘后同步与既有计算成功后保存当日市场复盘快照。未发布显示“当日复盘尚未更新”，不自动采集、不增加复杂缺失门禁。

## 并行开发任务与契约

### A：运行架构、共享状态与部署

负责 `main.py`、运行配置、新增薄内部代理／共享状态模块、`api/intraday.py`、`pipeline_jobs.py`、AI并发入口、部署和启动脚本。

1. 拆分生命周期；web 不运行行情、调度、分钟、财务、通知、挖掘恢复或自动完整性修复。collector 独占进程锁；网页重启不恢复／取消 collector 任务。
2. 明确代理路由：采集、配置修改、策略／监控修改、回测／AI执行、任务查询与取消转交 collector；行情读取留在 web。
3. 共享状态模块提供 `publish_quotes(quote_service)` 与 `publish_data_update(data_dir, datasets)`。前者保存本轮行情状态／指数／必要实时快照，后者发布本地数据变更。两个函数仅用于实现本次进程边界，不构建通用任务平台。
4. web 行情镜像先更新仓库和相关聚合缓存，再广播。网页 SSE 增加 `data_updated`，数据为 `{datasets: string[]}`；保留原行情、策略、告警、盘口与复盘事件。每个 web 进程只建立一条后台事件连接。
5. 保留现有回测重任务限额；AI使用有限并发，流式响应释放槽位；转发不重复取数、不增加自动重试链。
6. Compose 使用两个服务、共享卷、独立健康检查及自动重启；本地启动脚本启动两进程。记录备份／恢复步骤，不执行用户数据迁移或实际部署。

### B：本地查询、采集调度与复盘发布

负责 `api/kline.py`、`api/indices.py`、`api/financials.py`、`api/market_recap.py`，相关榜单服务、`quote_service.py`、`minute_refresh.py`、`trading_day.py`、`daily_pipeline.py` 与相关服务和测试。

1. 删除日线、单／批量分钟、指数查询中的隐式供应商调用。保留参数和响应口径；空数据返回原空态。`live` 参数继续接受，但只表示读取后台最新本地结果。
2. 榜单读写分开，GET 只读本机；collector 在后台更新包括当日的缓存。分析读取只能使用已保存数据。
3. 保存交易日历，collector 启动及定时更新，查询和时段逻辑不联网；盘后调度也按真实交易日门控。
4. 普通分时统一后台落盘，分时监控读取这份结果；与可选全量分钟避免重复采集。
5. 显式分钟获取和财务同步接入原 pipeline JobStore：响应新增 `job_id`，状态仍为 `pending/running/succeeded/failed`，取消保持现有协作式语义。`financials/status` 新增 `active_job_id`。
6. 后台成功写入后调用共享发布函数。行情广播前调用 `publish_quotes`；任务成功、分钟／榜单／财务更新后发布对应 datasets。
7. 新增 `GET /api/market-recap/publication?date=YYYY-MM-DD`（date 可省略，默认北京时间当日），响应 `{as_of, published, published_at, overview}`。overview 未发布时为 null，发布后为已保存快照。
8. 手动 AI 复盘在 collector 流生成完成时归档，并在 done 事件标记 `archived: true`；保留已有显式报告 CRUD 与 AI生成入口，不强制 AI成功才发布市场数据。

### C：前端契约与任务交互

负责 frontend 和相关测试，不改后端。

1. 删除多日分时图的自动同步与自动重试；显式获取展示原 pipeline 任务进度和取消。
2. 财务同步读取 `active_job_id`，展示进度并允许取消；现有 Data 页面任务恢复继续使用。
3. 新增集中查询键 `reviewPublication` 和 publication API 类型；复盘默认当日未发布时显示指定文案，市场数据使用已发布快照，AI／历史报告继续可用。
4. `data_updated` 按 datasets 失效分钟、日线、分析、财务、复盘与任务查询；SSE重连补读状态，保持最后有效数据，避免整个页面清空。
5. 默认实时间隔调整为30秒；同步新后端响应和现有 api.ts 调用方；不新增无需求权限／角色界面。

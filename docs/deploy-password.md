# 账号初始化与部署

服务必须登录后使用。账号库为空时，默认创建内置管理员，首次启动无需配置：

- 用户名：`pyxadmin`
- 密码：`19950412`

内置管理员可直接登录进入业务页面，不强制首次改密。若要自定义初始管理员，可在首次启动前于根目录 `.env` 或系统环境变量中同时设置以下两项；两项都留空时使用内置管理员，空账号库仅配置一项会报错：

```ini
AUTH_ADMIN_USERNAME=admin
AUTH_ADMIN_PASSWORD='请替换为至少8位的独立密码'
```

web 与 collector 必须使用同一个 `DATA_DIR` 和配置。账号权威存储为 `data/auth/auth.sqlite3`；仅在账号库尚无用户时创建初始管理员，已有账号时不会追加或重建内置管理员，后续修改环境变量或重启也不会覆盖现有账号及修改后的密码。源码仅内置默认密码的盐化散列。旧 `AUTH_PASSWORD`、`user_data/auth.json`、旧 Cookie 和 Bearer Token 不再提供登录权限。网页不提供注册或抢占首个管理员的入口。

管理员在“设置 → 用户管理”创建账号、设置角色、停用或恢复账号、重置密码。新建和重置后的临时密码必须先修改，才能进入业务页面。用户可在账号设置中修改自己的密码。密码长度为 8–128 位；`.env` 不要提交到 Git，文件权限建议为 `600`。

角色包括 admin、guest 和 pro。admin 管理共享采集、系统设置与账号；各角色的个人数据按用户 ID 隔离，管理员也不能切换身份读取他人的个人数据。pro 到期按北京时间到期日结束计算，届时按 guest 权限使用。

每个账号只有一个有效会话，新登录会撤销旧会话，有效期为 7 天。修改密码、停用账号及重置密码会撤销相关会话；角色调整在后续请求中按最新权限生效。登录事件保留 90 天，累计登录次数及最近登录时间/IP 保留在账号记录中。

退出和修改密码必须携带页面已确认账号的 `X-Expected-User`（或 `expected_user_id` 查询参数）；后端仍以有效 Cookie 会话确定身份，账号不匹配或未提供预期账号时返回 401，不撤销会话、修改密码或清除 Cookie。临时密码页面同样绑定账号；跨标签页切换账号后，旧页面锁定并重新载入。

## HTTPS 与反向代理

公网部署应使用 HTTPS。认证 Cookie 为 HttpOnly、SameSite=Strict；可设置 `AUTH_COOKIE_SECURE=true` 强制只通过 HTTPS 发送。默认不信任客户端提供的转发 IP；仅在确有反向代理时通过 `AUTH_TRUSTED_PROXIES` 配置代理的 IP/CIDR。写请求校验同源，确需额外来源时设置 `AUTH_ALLOWED_ORIGINS`，使用明确的来源列表。

所有官方启动入口已关闭 Uvicorn 的代理头预处理，由应用统一按 `AUTH_TRUSTED_PROXIES` 校验原始连接方。自定义启动命令也必须加 `--no-proxy-headers`，Python 启动则设置 `proxy_headers=False`；不要通过 Uvicorn 的 `FORWARDED_ALLOW_IPS` 替代应用配置，否则原始连接 IP 和协议会在认证校验前被改写。

## 升级、备份与恢复

首次升级时，程序将旧个人数据复制到初始管理员的 `data/users/<user_id>/`，保留旧文件且不覆盖已有目标；个人偏好只复制个人字段，共享系统配置留在原位置。迁移拒绝符号链接；遇到异常时检查日志和备份，不要删除源数据来绕过失败。初始管理员身份由账号库记录，不能通过改用户名重新分配旧数据。

备份与恢复应覆盖整个 `DATA_DIR`，包含账号库、迁移记录、共享数据及用户目录。忘记密码时优先由另一管理员重置；没有可用管理员时需由维护者在停服、完整备份后制定恢复方案。目前没有网页自助找回或命令行密码恢复入口。不要删除账号库或旧认证文件来重建账号，这不能安全恢复原有用户归属。

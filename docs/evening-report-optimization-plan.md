# 每日晚报优化方案

状态：首版已在 develop 工作区实施并完成本地验收（2026-11-12），尚未提交、合并或部署。交付观察名单、统一情绪与变量、低吸标签、自选股式表格及个人反馈记录。自学习、LLM 记忆与个性化排序留待后续讨论，不属于首版实施内容。实际验证、历史对照与剩余限制见[实施验收记录](evening-report-implementation.md#2026-11-12观察名单与个人记录)。

目标是每天按重点板块选出值得继续观察的个股，解释入选依据、位置与风险，让用户自行判断。低吸条件用于标签和提示，不再叠加成整张观察名单的前置门槛。首版采用程序生成可复现的基础名单，以表格呈现，在上方提供筛选条件；星标和盈亏只保存为可取消的反馈记录，不影响名单、默认排序或策略参数。

新规则版本为 `evening-v2`，名单版本为 `theme-observation-v1`，共用情绪版本为 `market-sentiment-v1`。[现有晚报设计](leading-stock-screening-design.md)保留旧版解释，本方案明确列出的策略调整替换对应旧规则，不与旧门槛层层相交；未改变的数据真实性、账号隔离、归档与恢复约定继续遵循 [维护约定](../CONTRIBUTING.md)、[盘后流水线](postmarket-pipeline.md)和[个人数据边界](secondary-development.md)。

## 1 目标与首版范围

### 1.1 交付结果

- 每日简短市场环境说明，分别呈现温度、承接质量、变化方向和周期阶段。
- 默认最多5个重点题材，每题材最多2只龙头和1只情绪股，合计最多15只不重复股票；允许不足额及有效空名单。
- 所有入选股票合并为一张类似自选股的表格，每行展示角色、关键数据、位置与低吸标签、风险和个人反馈按钮；详细理由可展开查看。
- 表格上方提供题材、角色、交易板块、低吸状态、星标和盈亏等筛选条件，以及代码／名称搜索。
- 个人页面首版提供观察历史和反馈概览；无反馈也可以正常使用晚报，暂不提供“我的记忆”入口。
- 历史推荐事实、个人反馈、客观回看、运行日志分开保存；首版不生成学习结论或记忆文件。

### 1.2 已确定的范围

观察股票沿用沪深主板、创业板非 ST 普通 A 股范围，排除科创板、北交所、B 股、ETF 和其他资产。证券资格以当时有效的标准化元数据为准，不能仅凭代码猜测。主板只分配龙头名额，龙头包含真龙和兜底龙；创业板优先是同等候选的排序偏好。

首版不执行交易、不推断用户持仓、不以收盘观察价伪造可成交买点，不输出未经验证的胜率。固定止损百分比在缺少真实入场信息时不能换算为用户的止损价。跨市场摘要、隔夜消息、盘中竞价和自动交易不作为首版依赖。

## 2 处理流程与职责

处理顺序为：正式输入就绪 → 共用市场变量与情绪 → 题材强度与范围 → 多路候选与角色 → 去重及配额 → 位置和低吸标签 → 共享报告归档 → 表格浏览与反馈记录 → 到期客观回看记录。

程序负责数值、日期、角色条件、风险事实、名额、去重、数据校验、归档和反馈统计。首版反馈只产生原始记录及确定性计数，不调用 LLM、不提炼偏好、不调整排序或阈值。后续是否引入自学习及如何使用这些记录，另行讨论。

## 3 数据与时点契约

### 3.1 股票范围与市场统计范围

观察股票范围和市场情绪统计范围分开保存。市场统计沿用共用环境服务的股票范围、ST 设置与方法版本；晚报和市场环境页在同一日期、同一范围下读取相同结果，不能因为个人观察偏好改变市场涨停家数。

题材成员数按本轮完整分类观察统计，不能先按晚报股票范围或候选池缩小人数，再绕过120只上限。历史题材关系使用当时可获得的成员证据；只能取得当前分类时，回算必须标明使用当前分类的限制，不能称为当时真实推荐。

### 3.2 价格与时间

- 日期、窗口和 D+1/D+3/D+5 均采用交易日，北京时间为业务时区。
- 涨跌停、炸板、一字板及交易限制基于原始价格和对应交易日规则；收益、均线、多空线等使用一致的复权序列。
- 所有计算只使用截止日已可获得的数据。历史使用因子时须保存所用数据版本，不能把后来修订的结果覆盖原报告。
- 20日收益需要目标日和20个市场交易日前的有效价格；60日高点需要完整定义的窗口。不能以12根日线或不足窗口替代。
- 收益比较遇到端点停牌时不自动挪用更早或更晚日期；缺行不等于停牌。技术指标沿用项目既有停牌处理，新增指标若采用不同窗口必须单独命名。
- 新增量能、振幅比的窗口包含全天停牌时，相关形态待核验，不把停牌零量、零振幅解释成有效缩量收敛信号。

### 3.3 硬校验与局部缺数

| 类型 | 处理 |
| --- | --- |
| 证券不在范围、状态不允许新增观察、当前价格或日期不可信 | 不进入当日新增观察名单，保留明确原因 |
| 某条入选理由必需的变量未知 | 该理由不可用，继续检查其他独立且证据完整的路径 |
| 缺少首波、E1/E2、贴线或低吸成交额信息 | 对应标签待核验，不否决已成立的观察理由 |
| 某个板块比较指标不完整 | 不给出虚假的完整排名，不拖累无关的可计算题材或独立候选路径 |
| 正式盘后基础输入未通过既有完整性验收 | 等待数据或报告失败，不能伪装成有效空名单 |

局部降级适用于可选分析和独立路径，不取消 [盘后流水线](postmarket-pipeline.md)对正式行情、因子、分类和发布状态的必要验收。首次运行或确认历史不足显示“确认积累中”，不自动解释为没有值得观察的个股。

## 4 可复用变量目录

每项变量保存 `value`、单位、公式与窗口、价格口径、统计范围、`as_of`、数据版本、规则版本及缺失原因。缺失值为未知，不补成零。新变量的比例统一采用小数制，界面显示百分比；辨识度为0—100分，空间分按下表公式计算并允许负值，成交额内部单位为元。

下表中 C/H/L 为一致复权价格，V 为标准化成交量，D 为目标交易日；原始价格识别的涨跌停标记由既有能力提供。

| 变量 | 首版定义与边界 |
| --- | --- |
| `limit_up/limit_down/max_consecutive/ge2_count` | 共用市场服务的涨停、跌停、最高连板、二板及以上家数，记录市场范围与覆盖情况 |
| `broken_rate/seal_rate` | 同一触板集合的炸板率与封板率，定义及零分母处理见第5.2节 |
| `promo_rate/promo_pool` | 复用现有连续可比交易日的晋级率与分母，样本不足为未知 |
| `limit_up_amount` | 当日收盘涨停集合的成交额合计，单位元，作为温度辅助证据，不单独触发综合标签 |
| `previous_limit_up_premium/previous_broken_performance` | 昨日涨停／炸板集合今日收盘表现，公式、样本和停牌处理见第5.3节 |
| `phase/heat_level/quality_level/sentiment_direction/sentiment_state` | 第5节的阶段、温度、质量、方向与综合标签，共用服务返回 |
| `return_3d/5d/10d/20d` | C(D)/C(D−N)−1，记录 N 与窗口完整性 |
| `limit_up_count_20d` | 截至 D 的最近20个市场交易日收盘涨停次数；已确认全天停牌不是涨停，未知日不能补零 |
| `consecutive_limit_ups` | 复用现有连续涨停口径，不将缺日拼接成连板 |
| `space_score` | min(100, return_20d / 0.80 × 100)，只用于对应空间条件；负收益不伪装成正空间 |
| `identity_score` | min(100, limit_up_count_20d × 18 + consecutive_limit_ups × 14) |
| `high_proximity` | C(D)/最近60日最高 H；0.85显示为85%，与板块相对领涨分分开 |
| `relative_lead_score` | 复用经核对的板块相对强弱证据，保留比较组、原公式与版本；不冒用 high_proximity |
| `acceleration_5_20` | return_5d / return_20d；分母≤0或缺失时不可计算，防止负数相除造成误判。此分母边界属于首版明确化口径 |
| `theme_strength_5d` | 第6节的涨停与未封板强势股时间衰减和 |
| `theme_member_count` | 完整分类观察中的去重成员数 |
| `amount_day/amount_median_20d` | 当日成交额与近20日成交额中位数，分别记录单位及窗口，不混用低吸当日档位和旧版流动性口径 |
| `bull_bear_line` | 复用 EMA10((H+L+C)/3)，与现有流水线 alpha=2/11、adjust=False 一致 |
| `distance_ma5/ma10/bull_bear` | C/对应均线−1；均线缺失则未知 |
| `volume_ratio_2_10` | mean(V(D−1), V(D)) / mean(V(D−11)…V(D−2))，两组不重叠，分母须大于0 |
| `daily_amplitude` | (H−L)/上一交易日 C；所用价格保持同一复权基准 |
| `amplitude_ratio_2_10` | 最近2日平均 daily_amplitude / 此前不重叠10日均值；零分母或窗口不完整则未知 |
| `first_wave_pullback` | 1−C(D)/已识别首波高点；没有可靠首波锚点则未知，不以60日高点代替 |
| `wave_index/first_pullback` | 主升波次和首波首次回调，列入待核验，首版不让 LLM 补成事实 |
| `intraday_drawdown` | 1−C/H，是明确的日内高点回撤；不直接等同“大面”或用户亏损 |
| `large_loss_count/loss_spreading` | “大面”数及亏损扩散尚待阈值、样本范围和比较窗口定稿，首版不参与确定性情绪分类 |
| `abnormal_move_proximity` | 保留现有各窗口及方向接近度；“近似触发”不等于官方严重异动事件 |
| `severe_event/near_severe_event` | 事件级严重异动及“即将严重异动”待核验，不直接由任意3日接近度代替 |
| `stock_role/role_status` | 主角色及确认、待复核、失效状态，分开记录 |
| `dip_status/dip_reasons` | 低吸确认、条件未满足、待核验、环境仅观察等结果，保留每项依据 |

变量定义应集中复用，不为晚报、环境页、个人历史和模型提示各算一套。上述目录是领域契约，不要求先创建通用指标注册框架。

## 5 情绪四维与综合标签

### 5.1 保留现有周期阶段

`phase` 继续使用现有 ice、ignite、rally、climax、ebb、repair，以及 unclassified、unknown。保留当前因果平滑、阶段持续确认和缺失处理，不因新综合标签删除原能力。

新增 `heat_level`、`quality_level`、`sentiment_direction`、`sentiment_state`。四个维度和综合标签由同一领域判定服务输出，页面只呈现结果及证据。首版标签是描述性研究参数，不代表收益预测。

### 5.2 温度和质量

记 N 为涨停家数、B 为炸板率、P 为昨日涨停股今日收盘溢价、J 为现有晋级率。

| 维度 | 首版分档 |
| --- | --- |
| 温度 | N＜40为低，40≤N＜60为中，N≥60为高 |
| 封板质量 | B＜25%为良好，25%≤B＜35%为分歧，B≥35%为脆弱 |
| 质量辅助证据 | 独立展示 J、跌停家数、昨日炸板股今日表现；未定义的大面与亏损扩散不参与首版判定 |

首版 `quality_level` 明确描述封板承接质量，辅助证据保留在 `quality_evidence`；暂不拼成未经校准的综合加权分。炸板率与封板率采用同一触板集合，分别为炸板数和收盘涨停数除以两者之和；零触板时二者未知，不能得到“100%优质”。两者不能当作两份独立证据。

### 5.3 昨日集合的今日表现

在 D−1 日收盘确定 U(D−1) 涨停集合和 F(D−1) 炸板未封住集合，计算：

`P(D) = mean[C_i(D)/C_i(D−1)−1, i 属于 U(D−1) 且两个端点可评价]`。

炸板集合表现采用相同公式，将 U 换为 F。集合按昨日事实确定，不能改用今天涨停集合，也不能事后只保留仍活跃的股票。主口径是等权收盘收益；开盘、最高价表现若新增，分别命名。

已确认停牌者单列，不混入有效均值；保存原始集合数、有效数、停牌数和其他缺数原因。非停牌缺数使该统计标记不完整，不用于确定性综合标签。首版有效样本不足10只时仍可展示样本均值，但标记小样本，不用它单独完成 hot、repair 或 cold 的溢价证据；这是与现有晋级率最小样本规模一致的研究初值，后续单独检查敏感性。

一字板和涨跌停股票仍可参与价格表现统计，另存成交限制。观察价格变化不包含“可买入并卖出”的假设。晋级率继续复用现有可比样本和最小池规则；`ge2_count=0` 是独立的低吸提示条件，不能被写成精确晋级率0。

### 5.4 方向投票

比较当天与此前5个完整交易日的均值，均值不含当天。分别给出改善、恶化或中性的一票：

| 指标变化 | 改善票 | 恶化票 |
| --- | --- | --- |
| 涨停家数 | 增加至少5家 | 减少至少5家 |
| 炸板率 | 降低至少3个百分点 | 升高至少3个百分点 |
| 涨停集合溢价 | 提高至少0.5个百分点 | 降低至少0.5个百分点 |

三票完整时，至少两票同向才输出改善或恶化，其余为震荡／分歧。缺少任何必要投票输入时方向为数据不足，已知单项变化仍可展示。参数先固定为首版研究初值，不能由 LLM 每天改动。

### 5.5 综合标签与冲突处理

| 标签 | 首版条件 |
| --- | --- |
| `hot_fragile` | N≥60 且 B≥35%，高热但脆弱 |
| `hot` | N≥60、B＜25%，且有效 P＞0 |
| `warm` | N≥60 且25%≤B＜35% |
| `cold` | N＜40、B≥35%，并有有效 P＜0或有效 J＜15%的至少一项独立负面证据 |
| `repair` | N＜60、B＜25%，有效 P 较此前5日均值提高至少0.5个百分点，且方向为改善 |
| `mixed` | 必需输入已知但未命中上述组合，展示常态／混合描述 |
| `unknown` | 必需输入不足，无法完成适用组合判断 |

高温分支先区分 hot_fragile、hot、warm；其余检查 cold、repair。各组合使用三态逻辑：已知成立的组合不被无关缺项覆盖；一个组合缺证据不能被强制算成失败后输出 mixed。N≥60且B≥35%绝不因炸板率单独归为 cold。后续只有“大面／亏损扩散”完成定义和验证后，才可通过新规则版本增加 cold 的证据分支。

方向作为独立后缀，例如“高热分歧，正在改善”。hot 不覆盖已知晋级弱、跌停增加等辅助风险，风险仍单列；不把综合标签当作全部风险的总开关。

### 5.6 对低吸提示的影响

观察名单不因任一情绪标签整体关闭。已确认 `phase=ebb` 或有效 `sentiment_state=cold` 时不输出低吸确认，只保留观察与原因。若二者均未触发且环境必需信息可判断，hot_fragile 下仍允许对通过低吸资格及 E1/E2 的标的显示“谨慎确认”；不因高热分歧直接否决。

phase 与综合标签冲突时，低吸环境限制优先，但两套原始结果同时保存。环境未知时低吸结果待核验，不冒用“没有风险”。修复、分歧等提示不自动换算为具体仓位。

## 6 板块主线与题材范围

### 6.1 首版强度公式

对题材 s：

`theme_strength_5d(s,D) = Σ(k=0…4) 2^(−k/2.5) × [U(s,D−k) + 0.5 × S(s,D−k)]`。

U 为当天收盘涨停家数；S 为未收盘涨停且当天涨幅≥7%的家数。两组互斥，每只股票在同一题材同一天只贡献一次。不同题材可以共享行情贡献，但第8节会对最终股票名额去重。

首版采用报告截止日 D 已知的完整题材成员，在这个固定成员集合上回看 D−4 至 D 的行情；U、S 均按该集合计数，并保存成员观察时点。这是“当前已知成员的近5日表现”，不是历史每天成员变化的复原，不额外要求已有5天分类快照。

历史报告的 D 必须使用当时已知成员，不能拿 D 之后取得的分类冒充。当时分类无法恢复时，只能形成明确标注当前分类限制的诊断回算。缺少必要行情时不将缺数当零、也不将1日累计冒充5日强度；可以保留当日结构说明，不能伪造完整主线排名。

### 6.2 范围与排序

地域题材、虚拟复盘类标签和成员超过120只的宽概念不参与主线名额。地域等排除复用明确标签及已有分类语义，不让模型凭名称猜测，也不误删“智慧城市”等产业标签。成员恰好120只不因上限被排除。

默认按完整5日强度降序选择最多5个有有效强势贡献的题材。同分比较当日涨停家数、最高连板，再按稳定题材标识排序；缺少辅助值不能淘汰已有完整强度的题材。

旧版超额收益、持续性、梯队、排名变化和板块轮次作为确认与解释依据，不再逐项相交成主线入口。行业保留为辅助背景，首版不再独立追加旧版“最多2只行业补充”名额。未来如启用行业替代题材，需单独定义范围及配额版本。

## 7 个股角色与多路观察

### 7.1 主分类顺序

先在范围内按独立特征寻找候选，再按“真龙 → 兜底龙 → 情绪股 → 跟风／其他观察”顺序形成互斥主分类。涨停、连板、大涨、新高等召回线索取并集，不要求所有线索同时出现；单纯命中线索不自动得到龙头身份。

| 主分类 | 首版条件 |
| --- | --- |
| 真龙 | return_20d≥50%、identity_score≥45、high_proximity≥85% |
| 兜底龙 | 未归真龙，且 return_20d≥30% **或** identity_score≥30 |
| 情绪股 | 未归前两类，且 return_5d≥12%、acceleration_5_20≥0.45、return_20d＜55% |
| 跟风／其他观察 | 无上述身份；附件所列低辨识度、远离高点、无连板、低涨幅可作说明，不占正式配额 |

兜底龙不额外要求“次级别核心”。板块相对地位、现有核心确认程度和独立韧性用于排序或理由，不能重新变成75分、70分、前2名等共同门槛。

若高优先级分类因缺数据不可判定，但另一条观察路径有完整证据，可以按可证明的较低角色暂列，并标明更高角色待核验。不能将未知真龙条件写成“确认不是龙头”。所有展示仍只使用一个主角色。

### 7.2 重叠与角色延续

真龙优先于兜底龙，兜底龙优先于情绪股；重叠时情绪属性作为副标签。例如20日上涨35%、同时满足加速条件的股票，主分类为兜底龙，可有情绪加速副标签，不能同时占龙头和情绪名额。

角色的当日条件与历史确认状态分别保存。原真龙的数值条件短暂不满足时进入“龙头跟踪待复核”，不继续宣称当天严格条件已满足，也不因一次断板直接降级。确认结构或地位失效后重新分类；满足兜底条件才降为兜底龙，否则不得强留兜底身份。跟踪待复核仍只占龙头名额，排序低于当日条件完整满足的同类候选。

“结构或地位失效”的新增数值定义见待核验项 T3。其启用前不自动声称降级已确认；历史身份作为带日期的证据保留。观察资格、当日角色条件和历史核心状态相互分离，旧连续确认不能重新成为候选入选前提。

### 7.3 补涨判断

情绪股不直接等于补涨股。补涨标签需有先行核心、启动先后、启动前相对位置和有效跟踪区间的证据；复用已有可验证时序，不以日线先后宣称盘中因果带动。证据不足显示“补涨待核验”，不否决已成立的情绪观察路径。

## 8 名单排序与配额

### 8.1 基础顺序

首版采用确定性排序。龙头名额中，先真龙、再兜底龙；同角色内先当日条件完整满足者、再历史跟踪待复核者。其后依次比较辨识度、20日涨幅、high_proximity；情绪名额依次比较加速比、5日涨幅、辨识度。同一排序层的未知辅助值单独标识并排在已知值之后，不能把它伪装成零。

客观排序项相同才应用创业板优先，最后按证券代码稳定排序。现有相对强弱、韧性、持续性先保留为证据，不拼接未经校准的新综合分。这个顺序是首版基准，后续通过固定样本比较其偏好，而非声称已找到最佳选股排序。

### 8.2 主题归属与去重

1. 在最多5个入选题材内，为股票确定唯一主题材：优先客观主线强度最高者，同分沿用第6节的题材次序。
2. 其他题材作为关联标签，个人偏好不改变客观主题归属。
3. 每题材按本题材候选顺序分配最多2个龙头、1个情绪名额；龙头包含真龙和兜底龙，二者共享2个名额。
4. 去重后不足额，可在同题材内递补下一只合格候选；不跨题材凑数，不将情绪空位自动改成第三只龙头。
5. 同股在正式表格中只显示一行、只占一个名额。跟风和未入选对象按需在折叠明细中显示“未入选，仅观察”，不混入正式15只上限的计数。

主板情绪股不分配正式名额；主板兜底龙可以。位置未到位、过热、破位或低吸未确认不会成为配额分配的统一否决条件，相关事实必须随股票行及其详情保留。页面上方的筛选只影响当前可见行，不重新分配名额或补选股票。

## 9 低吸信号与位置风险标签

### 9.1 与观察名单的关系

本节只决定低吸状态和提醒。默认先给出观察名单，再分别计算每项条件；不能把第9节结果逆向接入第8节作为入选必需条件。已知不满足与数据未知分开，不能将“未发现信号”写成“符合低吸”。

旧版近20日成交额中位数≥1亿元也不再作为观察名单的共同门槛，保留为流动性参考。它与下文当日成交额5亿／8亿及宽松档分别记录，不能因名称都叫成交额就替换窗口或重复筛选。

### 9.2 五道门

附件称“四重门”，实际列有五道；本方案统一称五道门。

| 门 | 首版使用方式 |
| --- | --- |
| 环境 | 按第5.6节；确认退潮或 cold 为环境仅观察，hot_fragile 不单独禁止 |
| 地位 | 龙头路径要求 space_score≥50、identity_score≥45、high_proximity≥85%；其中空间50对应20日涨幅40%，不等同真龙分类的50% |
| 承接 | 10%涨跌幅制度股票当日成交额≥5亿元，20%制度≥8亿元；首波人气宽松档分别为2.5亿、4亿元，仅在对应首波条件可核验后启用 |
| 情绪配合 | ge2_count=0时仅观察；未知则待核验，不能将它冒充晋级率0 |
| 首波回调 | 波次、首次回调、锚点须有可复现定义；未知时该门待核验，不能阻断观察名单 |

第一波加速豁免通道的附件参数为波次≥1、10日涨幅≥30%、5日涨幅≥3%、high_proximity≥85%。门⑤的附件条件还包括未形成主升波时20日涨幅≥20%、5日仍涨、high_proximity≥85%；已走至少2波不做；回调低于5%为跟随主升，超过5%进入回调观察区。因波次和首次回调尚无完整定义，这些分支首版记录为待核验；恰好5%的边界在 T2 中一并定稿，不能静默猜测。

情绪型低吸资格要求 identity_score≥60 且20日涨幅≥20%，还需满足对应其他条件。它读取情绪副标签及特征，不限于“主分类为情绪股”。否则在兜底条件为“辨识度≥30”的分类顺序下，这条分支永远不可达。兜底龙可以独立通过低吸资格，不能仅凭角色自动允许或禁止。

### 9.3 E1 与 E2

| 路径 | 附件数值条件与首版边界 |
| --- | --- |
| E1 压制形态 | 3日涨幅≤15%；volume_ratio_2_10≤0.65；距MA10为−2%至+6%且含边界；amplitude_ratio_2_10≤1.2。还须有“即将严重异动”的可靠适用依据 |
| E2 异动后形态 | volume_ratio_2_10≤0.55；L(D)＞L(D−1)＞L(D−2)；距多空线绝对值≤5%。还须有已发生严重异动及相应时点证据 |

五道门和路径前置均可判断且满足时，才给出相应低吸确认；hot_fragile 下改为谨慎确认。事件或波次未核验时，可以显示“数值形态符合，前置待核验”，不得缩写成 E1/E2 已确认。

晚报用完整日线确认的是盘后形态，不宣称在当天尾盘已经给出可成交信号。放量突破、再次站上均线等后续条件须等到实际出现后记录，不能提前写为完成。

### 9.4 风险呈现

距MA5、MA10、多空线距离、缩量、成交额档位、首波状态、缺口位置、异常波动接近度与破位各自显示。已知风险不能被高排名、个人反馈或页面排序消除。

多空线下方3%可以作为明确的价格位置标签；附件中的“不收回”需要相应观察时间，只有日线时只能说明收盘是否回到阈值上方。固定7%止损需要真实入场价，首版不推断、不将推荐日收盘自动当作用户成本。附件“已到位3只、临近2只、破位0只”的交易位置配额不用于本方案观察名单。

## 10 自选股式表格与个人反馈

### 10.1 页面布局与表格

页面沿用自选股的表格阅读方式：上方是报告日期／版本、简短市场环境和筛选栏，下方是一张合并所有入选股票的表格。每只股票一行，题材和角色作为列展示，默认顺序采用第8节的原报告顺序。

| 列组 | 首版展示 |
| --- | --- |
| 股票 | 名称、代码及交易板块标识，点击打开现有行情弹窗 |
| 题材与角色 | 主题材、真龙／兜底龙／情绪股及待复核状态；关联题材在详情查看 |
| 行情与强弱 | 报告日收盘价、当日涨跌幅、5日／20日涨幅、辨识度和当日成交额 |
| 观察依据 | 简短入选理由、位置与低吸状态；长内容通过明确的详情入口展开 |
| 风险 | 必要风险和待核验提示，不能被省略为含义不明的颜色 |
| 我的记录 | 五角星、红色“盈”方块、绿色“亏”方块 |

优先复用自选股使用的共用表格与数值格式，不复制自选股整页的分组管理、删除、自选持仓等无关行为。股票名称、反馈和关键状态在窄屏仍可操作；宽表内容在表格区域横向滚动，长理由与变量明细通过详情查看。若复用列配置能力，晚报配置须与自选股隔离。

表格行情列使用当前所选报告的历史时点，不能用实时行情替换原推荐事实。行情弹窗沿用现有当前行情能力，并清楚标明与历史报告的时点区别。首版不要求在每行增加分时或K线小图。

### 10.2 上方筛选与表头排序

筛选均默认“全部”，常用条件直接放在表格上方；窄屏允许换行，次要条件可收起。首版提供：

- 代码／名称搜索。
- 题材：按主归属题材筛选，关联题材仍可在详情查看。
- 主角色：真龙、兜底龙、情绪股；待复核状态作为补充条件。
- 交易板块：沪深主板、创业板。
- 低吸状态：已确认、谨慎确认、条件未满足、待核验、环境仅观察。
- 星标：全部、已星标、未星标；盈亏独立选择全部、盈、亏、未标记。

不同维度组合筛选，提供一键清除，并显示“当前显示数量／本报告总数量”。筛选后为空须提示“没有符合当前筛选的股票”，区别于原报告有效空名单、未生成或失败；筛选不回写报告、不触发重新选股或自动补足配额。

支持对已有数值列使用表头排序，并能恢复原报告顺序；缺失值与零分开处理。用户手动排序只改变浏览视图，不是自学习排序。切换报告日期或版本时，不串用旧结果；不适用于新报告的题材选择应清除或明确显示无匹配，不让上一份报告的行冒充新数据。

### 10.3 按钮外观

每行的“我的记录”列固定呈现三个简洁按钮，顺序为五角星、盈、亏，图形与文字如下：

| 按钮 | 外观 | 含义与状态 |
| --- | --- | --- |
| 审美 | 五角星图标；未选为空心，选中为实心并突出显示 | “符合我的审美”，不代表买入或赚钱 |
| 盈利 | 红色方块按钮，正中单字“盈” | 用户自报这次跟踪相关的盈利结果 |
| 亏损 | 绿色方块按钮，正中单字“亏” | 用户自报这次跟踪相关的亏损结果 |

红、绿方块均保留清晰文字对比；未选为浅色或描边，选中为明显实色，确保两者不会同时看起来已选。星标使用现有主题中的强调色；不以爱心、点赞、表情或只有颜色的色块替代。

按钮有可见焦点、键盘操作、明确的可访问名称和选中状态。悬停或聚焦说明分别为“符合我的审美”“我赚了”“我亏了”，选中后说明再次点击可取消；触屏不依赖悬停说明，点击区域与窄屏间距足够，不触发行情弹窗或整行操作。最终深浅主题、对比度和触控尺寸在页面验收时检查。

### 10.4 点击与取消规则

三个按钮都采用“点击选中，再次点击取消”。星标与盈亏是两个独立维度，允许“星标＋亏损”或“不星标＋盈利”；同一跟踪过程当前的盈、亏互斥。

| 当前状态与操作 | 保存结果 |
| --- | --- |
| 未星标时点击五角星 | 星标选中，盈亏状态不变 |
| 已星标时再次点击五角星 | 取消星标，盈亏状态不变 |
| 未标记盈亏时点击“盈”或“亏” | 选中对应结果，星标状态不变 |
| 已选“盈”时再次点击“盈”，或已选“亏”时再次点击“亏” | 取消当前盈亏标记，回到未标记，不自动选中另一项 |
| 已选“盈”时点击“亏”，或已选“亏”时点击“盈” | 替换盈亏结果，始终只选中一个，星标状态不变 |

未标记或取消均表示无此项反馈，不是负面偏好，也不推断未买入或实际持仓。五角星仅记录审美，不与自选股的加入／移除动作绑定。

每次修改保留事件时间、关联记录与设置／取消动作，统计以当前有效状态为准，不能把反复切换计成多条认可或多笔盈利。取消后从当前已标记数量中移除，历史可以查看这次取消记录。可选简短备注，不强制输入金额、交易价格或原因。

首版只记录这些事实，不启动自学习、生成记忆、调用模型或根据反馈调整推荐。记录未来如何用于学习另行讨论，不预先赋予训练权重或成功／失败标签。

保存中防止重复提交；保存失败恢复先前状态并显示可重试信息，不能只在界面上看起来保存成功。页面刷新、切换报告、重启后正确恢复；切换账号不能沿用上个账号的按钮状态。

### 10.5 个人页面

个人页面首版设置两个入口：

- 观察历史：按日期、题材、角色、星标、盈亏筛选，查看原推荐、跟踪过程、反馈变更和到期表现。
- 反馈概览：审美、自报盈亏、客观观察表现分区统计，显示各自样本数、未标记数、未到期和不可评价数量。

暂不提供“我的记忆”、自动整理、学习效果或个性化建议入口。这里的反馈概览是事实计数和价格记录，不提炼审美偏好或因果结论。

## 11 跟踪过程与客观回看

### 11.1 跟踪过程

同一账号对同一证券的连续推荐关联同一个跟踪过程（tracking episode），主板块或角色变化不自动拆分。首版以连续5份正常生成、日期连续推进的交易日晚报中均未出现作为结束条件；有效空名单计入缺席，报告失败、未生成和数据未知不计入缺席，并中断本次连续缺席计数，不能证明连续退出。

结束后再次出现创建新过程。过程中每次推荐仍保留独立日期和报告引用；反馈默认作用于该过程，保存发生时所看的具体推荐记录。一次星标在过程内只计一次认可。

### 11.2 客观观察表现

以推荐日 D 的收盘价为观察基准，分别计算 D+1、D+3、D+5 收盘相对 D 收盘的复权价格变化。同一窗口内价格与因子口径一致，保存评价截止日和数据版本。报告在收盘后产生，因此结果明确叫“推荐后价格表现”，不能称为实际交易收益。

目标日未到时为未到期；端点停牌、缺数或价格不可信时标记具体不可评价原因，不补零、不顺延到复牌日。涨跌停或一字板有有效价格时仍能计算价格变化，同时保留成交限制；不模拟一律可买可卖。

每天重复推荐可分别查看其窗口表现，过程级汇总使用该过程首次推荐作为固定锚点，不能挑选收益最好的一天。同一过程的多个窗口不是多个独立成功案例。首版只保存和展示这些客观记录，不用它们训练或调整策略。自报盈亏与客观表现分别统计，不合成统一成功率，也不以客观上涨替用户打“盈”。

## 12 记录存储与后续自学习范围

### 12.1 记录边界

| 记录 | 内容与维护方式 |
| --- | --- |
| 共享晚报 | 当时的市场判断、候选证据、角色、顺序、题材归属、限制及版本，程序生成 |
| 个人观察历史 | 引用报告和股票，保存跟踪过程、反馈当前状态与设置／取消事件 |
| 客观回看 | 到期窗口、样本状态、价格变化及所用数据版本，程序计算 |
| 运行日志 | 任务、失败、重试、耗时和用量，沿用现有日志机制 |

历史按月份组织，个人记录引用共享报告，不复制全份报告和K线。新的反馈和回看结果追加到关联记录，不改写过去的入选理由。数据修订或重新生成产生新修订，保留原发布及修订说明。

每次推荐至少保存报告版本、规则版本、范围版本、数据截止时间与来源版本、情绪判定结果、支撑入选的变量值、主角色及状态、主题材和原始推荐顺序。浏览时的临时筛选、表头排序不改写这些事实，也不要求另存一份推荐报告。首版不为了未来学习预建记忆版本、训练任务或模型调用记录。

### 12.2 账号与环境

个人数据沿用 `data/users/<user_id>/` 下的隔离能力，具体文件名在实现中按既有存储方式决定。这里的“本地”指运行服务所在磁盘：本机开发存本机，服务器运行存服务器。代码发布不复制或覆盖不同环境的反馈、账号和配置。

归属从可信会话或后台用户上下文取得，不能由请求中的 owner 任意指定。个人反馈不写进共享市场报告，也不能串入其他账号的页面或缓存。

### 12.3 自学习留待后续讨论

此前讨论过的 LLM 记忆整理、20—30条及3000字以内的容量、锁定纠正删除、个人提醒和受限排序，均作为后续讨论背景，不是首版要求。首版不创建记忆文件、学习任务、模型入口或占位的“我的记忆”页面。

后续重新讨论时，需要确定学习目标、使用哪些记录、取消／纠正反馈如何处理、如何避免重复样本、何时整理、模型用量，以及允许影响哪些展示或策略行为。在这些问题形成新的方案前，星标、盈亏和客观回看只作为独立原始记录保存，不自动产生经验结论或策略变化。

### 12.4 候选审计与评价落盘契约（2026-11-12补充）

归档中的入选与可比候选快照是推荐时特征的权威，不另复制一份候选行情；各层保存范围与期限见12.5。审计范围是实际进入晚报计算的证券；其中只有硬校验、题材、角色与名额资格均通过的股票进入可比候选池。未知和已知不满足分别保留，步骤确实没有执行才标 `not_executed`。当前实现独立计算角色，即使题材未进前5也不把角色写成“未执行”。

每只股票的 `observation.decision` 保存步骤结果、首个阻断步骤、决定性原因码和全部原因码；同时保存题材内／全局同名额排名、实际竞争与占用名额、是否允许降级竞争，以及竞争题材、最终归属和去重依据。排序、去重、比较组定义分别带版本。比较组限定同日、主题材、名额类型、角色状态、角色条件完整度和数据完整度；审计用的硬失败或缺数组不能混作仅因配额落选的反事实组。

连续值复用 `variables.<字段>.value`（即原始连续值），保留单位、公式、时点、数据与规则版本；不另造 `raw_value` 同义副本。`bucket_label_at_time` 和 `bucket_rule_version` 同存，当前没有采用数值分桶时均为 `null`，不编造阈值。未来重分桶应生成带版本的分析结果，不能改写原值或历史桶标签。情绪维度保存在报告的 `market.sentiment.classification`，股票快照引用该报告版本。

题材审计保存完整成员数、排名分母、范围、时点、规则版本及强度原值；宽概念和地域是题材属性，不生成股票级排除标记。全部关联题材数与前5关联数分开。当日角色复用 `daily_role`，历史身份另存 `role_by_history_tracking`，并保留角色条件缺失项。首波、波次、补涨和严重异动有独立核验状态及原因；近似异动继续保存窗口、基准、阈值和近似说明。入选和配额落选股票使用相同的位置明细计算，避免只为入选组计算特征。

落盘边界如下：

| 存储 | 职责 |
| --- | --- |
| 原报告及修订归档 | 不可变特征、决策、市场状态、题材审计；`as_of`表示事实日期，`data_cutoff`表示输入截止，报告的`generated_at`／`version`表示实际生成时间和修订身份 |
| `recommendations`、`episodes` | 个人推荐引用、不可变观察快照及跟踪过程；反馈仍在各账号数据库 |
| `audit_cohorts` | 独立的`audit:<报告版本>:<证券>`标识、候选引用和分析索引；不创建个人过程、不接受反馈、不计认可次数 |
| `outcome_evaluations` | 推荐时特征之外的客观结果；同一证券、推荐日只有一份，由候选及各报告修订共同引用 |
| `audit_analyses` | 按报告版本、分析规则版本和数据版本追加缺失率检查；原分析不被新版本覆盖 |

回看复用既有字段：`status`为未到期／可评价／不可评价，`reason_code`为结构化原因，`trading_constraints`独立记录成交限制，`window`／`target_date`／`evaluated_at`保存窗口及评价时间；`return`明确为小数制价格变化。另存两端原始与复权收盘价、`adjust_method`、统一`adjust_base_date`、复权规则、数据、日历及停牌来源。回看从原始价重新应用截至基准日的复权因子，不复用报告当时的复权值；因子缺失或非法不视作“无需复权”。停牌或价格不可信保持`null + reason`，不补零、不顺延。当天已记录的ST／涨跌停事实可以保留，缺少历史资格时明确未知，不能用当前资格倒推历史；这不自动否决可信的价格变化计算。

推荐计数键固定为账号、证券、过程、报告交易日；`appearance_seq`按不同推荐日递增，`revision_seq`只记录同日修订。保留首发引用与最新修订引用，默认以首发修订作为样本身份、最新修订作为可选事实展示；个人概览的推荐次数排除修订，修订数量另列。过程首次推荐是固定评价锚点。过程结束记录`ended_at`、`end_known_at`、`end_reason`；推荐快照只记录当时已知的缺席数，后来的结束信息不写入旧特征。

缺失率检查分别输出入选／全部未入选、入选／可比配额落选，以及可比候选中各窗口可评价／不可评价的样本数、缺失数、缺失率和差值。某特征只在第一组有值时明确提示不能直接归因。所有输出携带同周期样本数和“同周期及重叠窗口样本不独立，只能作关联观察”的提示；当前不在单日相关样本上伪造统计显著性结论，跨日显著性方法需另定分析口径。

已有数据库只在独立派生任务的写事务内升级：迁出旧回看结果、保留过程和反馈引用、由已有日期及修订推导序号；旧特征缺失的字段和获知时间不补造。GET不触发迁移。已完成窗口通过索引排除出待评价扫描；审计分析只重读受影响推荐日，不为每条候选重复计算价格或扫描整份历史归档。

新生成的观察名单采用`evening-storage-v2`。精简发生在已完成计算与分配后的持久化边界，不改变候选资格、排序、配额或个人反馈语义，不再永久保存全市场逐股中间计算。

| 层 | 保存范围 | 保留期限 |

范围外股票只进入聚合计数，不创建逐股审计。`quota_eligibility`表示名额资格不符，`allocation`表示实际竞争后的名额耗尽，不能混成一个原因。“可比候选组”仍存在排序强弱差异，不代表已经消除选择偏差；所有缺失率的“全部未入选”均只指实际评估集合。审计过期后若重新分析，明确标注`audit_retention_complete=false`，不拿剩余候选冒充完整审计分母。

共同的报告版本、规则、范围、数据版本、事实日`as_of`与输入截止时间在封套保存；字段继承，具有不同口径时单独注明。变量定义只存一份，逐股保存连续值、缺失原因与覆盖项，读取时还原既有接口；`values`由权威`variables`投影。旧完整归档仍按旧格式读取，不自动改写或清理。

保留期适用范围必须有格式证据：输入清理仅覆盖新写入的`.json.gz`，旧`.json`以及任意旧／未知格式原版或修订引用的输入均保留，其完整就绪入口同步保留。数据库审计按发布索引中明确标记`evening-storage-v2`的报告版本清理，不能只按日期或数据库登记时间推断；缺少格式证据时不删。共享评价不按审计期限清理，旧格式曾生成的审计对象评价继续保留。

原发布与每次修订分别保存，先写全部分层文件，再原子公开索引／修订清单；不同修订不会被同日“最终态”覆盖。新归档不另存完整页面副本，GET只从小型长期档案投影入选行，不读取中期审计、运行状态或原行情。连续计算单独读取滚动状态，原版与修订分支不串用。

评价结果永久保存推荐日与目标日原始收盘、统一基准下复权收盘、实际采用的两端调整倍数、基准日及规则／数据版本，可以独立复核收益公式。目标日证据由后续评价任务追加，不伪装为推荐时已知事实；已经完成的评价不随后来行情修订覆盖。

本期承诺是**原推荐事实可核验、回看结果可核验、冻结候选集合内可复算**。候选边界通过完整快照引用保留排序输入，可在该集合内调整名额、取前N或重新排序；不支持引入未保存的证券、扩大题材范围或改变更早硬条件。完整输入或前向状态过期后，历史全市场修订明确拒绝；行情文件引用也不能恢复供应商后来修订前的原数据。全市场历史输入版本化不在本期范围。

collector启动后及北京时间02:10至05:10每小时检查一次维护任务，当天成功或手动取消后不再自动执行；繁忙／失败留待下一次检查。任务复用原写入槽与取消机制，不暂停行情、不触发市场缓存刷新。只清理晚报目录中到期的新格式文件及共享库的审计索引／分析，拒绝越界链接；候选、推荐、评价和账号反馈不作为删除目标。文件按项删除，取消保留已完成的到期清理；数据库提交前取消则回滚该事务。SQLite释放页由后续写入复用，不承诺每次删除后文件立即缩小。过期审计不再保留副本。

本方案作为后续实施的共同契约。每个阶段继承数据时点、主角色互斥、低吸不否决观察、账号隔离和历史不回写等约束，不在局部任务中另定口径。

| 顺序 | 交付结果与范围 | 前置与验证 |
| --- | --- | --- |
| S0 数据与现状核对 | 确认此前正式历史日线标记及无关缺数传播修复已在目标环境验证；检查可用历史和分类时点，明确新旧规则版本 | 同输入比较和对应既有回归；不自动覆盖运行数据，也不把本地验证当成已部署 |
| S1 共用变量与情绪 | 落实变量单位、昨日集合表现、四维与综合标签；保留原阶段；晚报和环境页共用结果 | 固定数值与日期样本，阈值边界、空集合、小样本、方向、缺失及多页面一致性 |
| S2 板块与基础名单 | 题材强度、角色、主归属、去重和2加1配额；撤销旧全站5只和观察路径共同门槛 | 确定性候选样本、首日／缺历史、重叠角色、多题材、局部缺数和不足额；同批历史对照 |
| S3 表格与筛选 | 使用自选股式表格，增加上方筛选、表头排序、位置／低吸／风险列和详情；可计算条件先上线，未核验条件明示 | 低吸失败仍能入选；筛选不重选、排序不改归档；桌面、窄屏、历史切换和构建 |
| S4 反馈与历史 | 五角星、红色盈方块、绿色亏方块；过程关联、月度记录、1/3/5日回看和个人页面 | 互斥／取消／失败恢复、账号隔离、幂等、重启、时间对齐、过程去重、样本分母 |
| S5 集成验收与规则评估 | 完成全链路检查、新旧版本读取及固定样本比较；确认反馈只记录；自学习另行讨论 | 对照第15节，更新当前实现文档；部署继续遵循 develop验证后再合入main的项目约定 |

S0—S5的代码、接口与本地验收已完成；新盘后派生任务已同步至[盘后流水线](postmarket-pipeline.md)及对应测试。目标服务器的正式补采、部署和前向效果评价仍未执行，不能由本地通过推定完成。

### 13.1 调度与失败隔离

继续保持步骤8保存晚报就绪证据、主管道释放写入槽后独立生成晚报。后续可选步骤失败不抹掉已就绪证据；手动取消按原语义停止自动派生和重试。新变量所需数据遵循原始行情、因子、指标、环境的依赖顺序。

客观回看依赖已经发布的报告及到期数据，失败不撤回共享报告、不触发无关行情重采。首版不接入记忆整理或自学习调度。共享报告 GET 和个人历史 GET 保持只读，不能打开页面就自动联网补数、生成报告或调用模型。

### 13.2 存储与缓存

共享报告更新只失效报告相关读取。个人反馈更新只失效该账号的反馈、历史和概览，不清空市场缓存。复用已有查询键、事件和批量读取，避免每行独立扫描历史；上方筛选和手动排序在已有报告结果上完成。

个人反馈原子保存，重复请求不重复创建反馈；并发编辑采用明确版本检查或等效的已有机制，不能静默丢失另一端修改。设置和取消采用相同保存契约，失败不能让表格状态与持久化记录长期不一致。

旧报告缺少新字段时标记“旧版未记录”，不补造成当时已经计算。新旧状态按规则及范围版本隔离；后来的反馈不能倒灌改写旧推荐理由。取消、重启和重试沿用现有任务恢复规则。

## 15 验收标准

### 15.1 功能与口径

| 编号 | 可执行场景 | 必须观察到的结果 |
| --- | --- | --- |
| A1 | 有完整观察理由，但缩量、贴线、成交额、首波或E1/E2不满足 | 仍可分配观察名额，对应低吸状态和原因准确展示 |
| A2 | 正式行情缺失或价格日期不可信 | 等待／失败或排除受影响路径，不能假装有效空名单或完整推荐 |
| A3 | N=60、B=35% | hot_fragile，不为cold；其他溢价缺项不能覆盖这个已知组合 |
| A4 | N=60，B分别略低于25%、等于25%、略低于35% | 结合P的值与有效性准确区分hot、warm、mixed及unknown，边界不混淆 |
| A5 | N=39、B=35%，P/J均无负面证据，随后加入有效负P或低J | 前者不判cold，后者按组合判cold；炸板率不能单独触发 |
| A6 | 同样的绝对温度与炸板率，历史变化方向相反 | 综合标签可相同，改善／恶化后缀不同；5日参照不包含当天 |
| A7 | 昨日涨停集合、今日涨停集合不同；有停牌、一字板、缺数和除权样本 | 溢价使用昨日集合、统一复权端点、正确覆盖数；不推断可成交收益 |
| A8 | 触板数为0或晋级样本不足 | 保持未知／小样本，不制造完美封板率或晋级率0 |
| A9 | 某股票同时满足兜底与情绪条件 | 主分类为兜底，情绪为副标签，只占一次龙头名额 |
| A10 | 20日涨幅不足30%但辨识度≥30 | 在其他硬校验通过时可归兜底，证明“或”未被写成“且” |
| A11 | 具情绪副标签的兜底龙达到情绪型低吸资格 | 相应路径可被计算，不因主分类而变成不可达分支 |
| A12 | 真龙条件短暂失配、单次断板或确认破坏 | 按角色状态区分待复核与确认降级，不当天双计；T3未关闭不伪造确认 |
| A13 | 同股属于多个入选题材，某题材不足额，且主板存在情绪股 | 主归属稳定、去重后按本题材递补、不跨题材凑数；主板情绪股不占正式名额 |
| A14 | 已有5日行情和报告当日分类，5个题材均有足够不同候选，另含宽概念和地域标签 | 无需额外5天分类快照即可计算；最多15只且每题材2加1；宽概念人数按完整成员统计 |
| A15 | 缺首波或严重异动前置，但E1/E2数值形态满足 | 显示“数值形态符合，前置待核验”，不能显示完整低吸确认 |
| A16 | 查看历史日期的缺口、环境和推荐 | 只读当时事实或明确修订，未来价格、今日分类及后来的反馈不倒灌改写推荐 |

### 15.3 验证方法与效果评估

实施时选择与变更匹配的证据：后端对应模块测试和固定数值样本、真实存储读写与任务恢复、前端交互与生产构建、桌面和窄屏手工检查。复用 `test_evening_report_rules.py`、`test_evening_report_engine.py`、`test_evening_report_infra.py`、情绪及个人数据相关测试入口；新增测试验证具体风险和用户行为，不机械重复实现。

候选数据补充由 `test_evening_report_audit.py` 与tracking测试验证：三态及未执行语义、配额前双排名、题材级排除、相同特征计算、候选与个人身份分离、同日修订不重复计数、统一复权端点、历史限制来源、缺失率及分析版本留存、旧库升级和推荐快照不回写。

历史比较使用同一份股票、指数、分类和日历输入，按交易日顺序计算，记录每条路径召回数、排除原因、各角色数量、最终去重数量、低吸状态分布及名单变动。至少覆盖热度高但质量差、冷清、修复、缺历史、局部缺数和候选重叠的样本。缺乏真实时点分类时，明确回算限制并补做前向观察。

功能验收不要求每天凑满15只，也不以盈利为通过条件。效果评估看观察覆盖、理由可信度、名单稳定性、空名单原因及用户反馈样本；星标比例、自报盈亏分布、客观价格表现分别报告分母。参数调整必须以新规则版本记录，不能借学习自动改写旧结果。

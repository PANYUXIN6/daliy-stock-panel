# 因子平台

本文记录现有研究入口、策略流转和未完成的研究设想。公式、DSL、统计口径与数据要求见 [因子计算与研究口径](factor-system-design.md)；实现定位见 [仓库地图](REPO_MAP.md)。

## 1. 研究与策略

因子研究比较截面排名、IC、分层和多空表现；策略负责信号时机、交易规则、仓位、成本与风险。研究结果可通过已有策略的评分配置、声明式条件信号及候选方案进入策略验证。新增 Python 策略由服务器维护者部署。

```text
因子注册表 → 检验／公式编辑／组合／挖掘
                 ↓ 评分配置／条件信号／候选方案
              策略筛选 → 回测与验证
```

目录元数据来自 `backend/app/factors/registry.py`。当前内置因子、个人公式、复合因子和扩展字段共用目录与依赖解析；不在文档中维护固定数量或复制整份因子清单。

## 2. 页面与导航

`frontend/src/pages/Factors.tsx` 承载 `/factors`，tab 状态存于 URL：

| 参数 | 页面 | 实现 |
| --- | --- | --- |
| `tab=inspect`（默认） | 批量／单因子检验 | `pages/backtest/FactorDiscovery.tsx`、`FactorBacktest.tsx` |
| `tab=library` | 因子目录与详情 | `pages/factors/FactorLibrary.tsx` |
| `tab=editor` | 公式编辑、校验与试算 | `pages/factors/FactorEditor.tsx` |
| `tab=composite` | 成员权重组合 | `pages/factors/FactorComposite.tsx` |
| `tab=mining` | 因子与策略挖掘 | `pages/backtest/MiningWorkbench.tsx` |

因子库“去检验”使用 `?tab=inspect&focus=<id>`；编辑使用 `?tab=editor&edit=<id>`。`/backtest?tab=factor`、`/backtest?tab=mining` 和 `/mining` 的兼容跳转保留已有查询参数。

因子页和回测页共用 `ResearchCandidatesDialog`。管理员可将候选带入策略回测页复测；候选定义与存储由 `backtest/candidates.py` 管理，不能因前端搬动入口而改变历史配置。

## 3. 检验

### 3.1 计算入口

单因子与批量检验调用 `/api/backtest/factor/run` 和 `/batch`，由 `FactorBacktestService` 计算 Rank IC、分层净值、多空、覆盖率、换手及分年／衰减／分环境结果。虚拟、自定义、复合因子先通过共享物化路径补齐依赖。

财务依赖在显式研究任务中按需准备，时间可用性仍由财报版本门控；读取已有研究结果不自动补数。成本、资产类型、时间窗口、调仓频率和权重方式属于研究配置，保存候选时继续保留。

### 3.2 选择与预设

检验页提供全面、快速、趋势动量、超跌反转、量价资金和财务价值预设。它们从接口目录按分组生成，数量随当前目录变化；搜索只过滤展示，手工选择保留在当前配置中。

### 3.3 结果判读

`FactorDiscovery.tsx::verdictOf` 当前按下列条件展示徽章：

- 有 NW t 时：显著性为 `|t|≥2` 且 q 缺失或 `q≤0.1`；预测力为 `|IC|≥0.02`。两者均满足显示有效，只满足其一显示边缘。
- 无 NW t 时：退回 `|IC|≥0.02`、`|IR|≥0.3` 的经验规则，两者均满足显示有效，只满足其一显示边缘。
- 计算失败单独显示错误；其他结果显示无效。

t/q 由后端计算，徽章由前端根据这些数值推导，并非服务端返回 verdict。经验阈值和统计显著性不能证明样本外持续有效。多空为理论组合，A 股可执行性和成交约束仍需策略回测。

### 3.4 单因子与候选

批量结果可进入单因子详情并返回，研究结果可保存为候选。单因子图表和表格复用检验引擎输出，不另写计算公式；候选保存不等于晋升或自动交易。

### 3.5 自动挖掘

检验页可发起 `/api/backtest/mining/auto`。`services/auto_mining.py` 先按所选门槛筛选因子并记录达标清单和失败原因，再复用相关性剪枝、束搜索、嵌套样本外和晋升规则。组合搜索本身不依赖 LLM；任务执行与恢复见 [挖掘说明](mining.md)。

### 3.6 因子方向

结果中的方向取本次样本 `ic_mean` 符号：正值表示值大看多，负值表示值小看多，空值和错误不显示。它描述当前样本，不是因子永久方向。注册表默认 `direction=none`，策略可通过 `scoring_directions` 明确覆盖。

## 4. 因子库与公式编辑

因子库从 `GET /api/factors` 读取类型、公式、预热、资产与依赖，支持搜索、分组和类型筛选。详情提供检验、个人因子编辑、分组／状态修改和删除；删除引用冲突由后端检查并返回清单。

编辑器提供内置模板与已保存公式载入、算子和字段插入、结构化校验及试算。`POST /api/factors/validate` 返回依赖和预热，`/trial` 使用最近交易日面板计算 IC。保存时后端再次校验并要求非空输出，不能仅依赖浏览器按钮状态。

个人定义存于当前用户的 `user_data/custom_factors/`，由 `store.py` 管理。修改公式提升版本并回草稿；名称或分组编辑保留状态。`draft/active/watch/retired` 可手动设置，但当前没有完整检验后自动转正、退役因子统一禁止策略引用或后台巡检任务。

## 5. 组合

组合页支持从基础／虚拟目录选择 2–8 个成员，提供均等和手动权重。保存后成为 `cf_` 因子，可在检验与策略评分中引用。

当前值为 `Σ weight_i × 截面zscore(member_i)`，由 `strategy/scoring.py` 统一计算。后端可以校验注册成员和递归依赖；当前页面选择范围比底层成员协议窄。没有 ICIR 自动权重、独立 transform 选择、截尾／中性化管线或组合预览曲线。

## 6. 策略接入

| 入口 | 当前行为 |
| --- | --- |
| 评分配置 | 内置、个人与复合因子可通过 `scoring` 及方向配置参与排序 |
| 因子条件信号 | `AddFactorSignalDialog` 将因子与阈值保存为条件信号，可接入策略触发器 |
| 因子库“生成策略” | `GenerateFactorStrategyDialog` 仅显示服务器部署说明；网页不生成或保存 Python 策略，相关保存和发布接口由服务端拒绝 |
| 候选复测 | 共用候选弹窗将研究配置带入策略回测 |
| 因子归因 | 策略回测保存入场候选因子快照，对胜／败交易比较均值；`META.scoring` 为空的矩阵单因子排名策略当前不产出该归因 |

能力与权限分别由当前账号规则约束。后台计算、前端入口和 AI 调用都需复用相同边界，个人使用不改变已有数据隔离与会话要求。

## 7. 尚未实现的研究设想

- 后台衰减巡检和独立巡检视图：原设想使用滚动 63 日 IC／IR，衰减后进入 watch，连续观察后考虑 retired。阈值、任务时段和对存量策略的影响尚未接线；状态字段已存在不代表自动规则生效。
- ICIR 自动组合权重：原设想为 504 个交易日窗口，仅使用截至 t−1 的信息；当前仅手动／均等权重。
- 点时宇宙、中性化、三口径报告、单调性、IC 半衰期，以及 DSR 接入挖掘晋升：详见 [研究口径中的设想](factor-system-design.md#4-研究宇宙研究设想尚未实现)。
- LLM 从失败模式提出新 DSL 公式的流程尚未实现，不与现有确定性组合搜索混同。

这些是保留的研究方向，不是固定实施批次或当前验收门槛。

## 8. 维护与验证

前端请求与类型在 `frontend/src/lib/api.ts`，查询键在 `queryKeys.ts`。改动后按 [维护约定](../CONTRIBUTING.md#9-验证矩阵) 选择定向验证；后端公式、目录、存储、统计和研究测试入口见 [研究口径](factor-system-design.md#13-定向验证入口)，前端现有 `FactorDiscovery.test.tsx`。

源码检查用于确认接口和路径；公式或交互变更还需对应的数值与页面验证。

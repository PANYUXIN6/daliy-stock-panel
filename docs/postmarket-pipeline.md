# 交易日盘后同步顺序约定

本约定依据 2026-10-18 的需求制定，后续新增盘后数据步骤必须遵守以下依赖顺序。

## 调度与执行归属

- 由 **collector** 的既有调度器执行，默认北京时间 **16:00** 启动。本地交易日历必须明确确认当天为交易日；休市或日期未知时不执行，不能用周一至周五替代交易日判断。
- 16:00 是开始尝试同步的时间，不代表供应商保证数据已经发布齐全。正式日线未齐、供应商失败或执行槽繁忙时，当天每 15 分钟再检查，最后一次检查为 23:45。默认时点可通过既有 `pipeline-schedule` 偏好接口延后，不能早于 16:00；历史更早配置按 16:00 生效。
- 自动和手动任务共用 JobStore、唯一数据写入槽、重任务容量控制、进度与取消接口。运行期间暂停实时行情，计算、刷新和发布完成后释放执行槽。
- 调度器启动时检查一次；日历尚未准备好时，在下一次 15 分钟检查继续处理。按当日成功任务的持久化记录去重，网页重启不触发重复同步；collector 重启后也读取既有任务历史。任务历史被人工删除后允许再次执行。
- 手动取消自动任务后，当天不再自动重试；次一交易日恢复正常。上游失败或进度超时不等同于手动取消，仍允许当天重试。排队任务跨日期后不得再作为原交易日任务执行。

## 固定执行顺序

| 顺序 | 阶段 | 执行与完成条件 |
| --- | --- | --- |
| 1 | 个股维表、股票池 | 重新同步当日完整股票维表，以本轮维表构建 A 股股票池，排除尚未上市标的；交易所请求失败不能保存半套维表并宣称完整。 |
| 2 | 股票正式日线 | 通过当前日线数据源拉取官方历史日线，增量覆盖最新日期和已知缺口；首次仍按原管道回填一年。自动任务不能走实时快照覆写分支。立即核验本轮返回是否覆盖当日股票池，旧文件不能代替本轮取数成功。 |
| 3 | 除权因子 | 使用已配置的因子路由，与日线范围对齐；失败批次必须阻止本轮复权指标和环境计算，不能把网络失败当成“没有除权事件”。 |
| 4 | 股票 Enriched 指标 | 正式日线与因子就绪后加工。当天已有实时指标分区也重新加工，覆盖仅成交量、成交额被修订的情形；历史受因子变更影响的标的沿用已有局部重算。 |
| 5 | 核心指数、可选 ETF | 核心四指数使用 `index_const.py` 的权威清单同步正式日线；ETF 继续按已有开关同步日线、因子和指标。股票、指数、ETF 保持独立存储。 |
| 6 | 当日数据验收、缓存刷新 | 核验本轮股票日线、核心指数，以及落盘股票指标的日期、标的覆盖、数值一致性和发布状态。验收成功后刷新仓库缓存，环境计算才能读取新数据。 |
| 7 | 概念、行业分类 | 复用板块分类同步服务，顺序更新概念、行业两表并清除映射缓存；失败不使用陈旧分类继续生成本轮主线。 |
| 8 | 市场环境、情绪周期、主线 | 增量补算环境缺口和被改写的日期，再重标完整情绪周期；晋级率计算读取前一实际交易日的连板数据，本轮必须生成当日环境与阶段，不能沿用旧的当日结果宣称成功。概念、行业主线依次计算，补历史缺口并刷新当天结果。当天没有满足条件的主线可以为空。 |
| 9 | 模拟盘结算 | 复用既有逐用户结算，按正式日线和因子处理；重试须沿用已有订单与公司行动去重。 |
| 10 | 可选分钟历史 | 仅在原分钟同步开关开启且能力可用时执行，沿用首次回溯、后续增量规则。排在环境之后，避免全市场分钟历史阻塞核心分析。 |
| 11 | 五档盘口 | 数据源具备能力时调用原盘后定版能力；无能力则跳过。它不是环境评分的前置数据。 |
| 12 | 竞价风向标、龙虎榜 | 顺序调用现有专有数据服务；缺少来源或上游尚未发布时保留明确状态与真实数据日期。它们不属于步骤 6 的全市场日线验收范围，不能因为管道完成就声称榜单已经齐全。 |
| 13 | 复盘快照、共享更新发布 | 前序必需步骤成功后发布当日市场复盘快照；刷新 collector 缓存并发布共享快照和 `data_updated`，使 web 与前端查询失效。部分写入失败时也刷新已保存的数据，但任务必须保持失败状态。 |
| 14 | 可选周度研究 | 只有同步任务成功且已经释放写入槽、重任务容量后，才按原周度开关与日期规则触发挖掘。不占用同步槽运行研究。 |

上述“当日数据齐全”专指支撑环境分析的正式股票行情、核心指数和股票指标。不能用一个当日分区、全局最大日期、实时快照或固定覆盖百分比替代验收。

## 停牌、数据源与缓存契约

- 本轮正式日线中明确的零开盘／最高价或零成交量额记录，按现有停牌过滤口径记录为停牌证据，不参与市场涨跌和指标统计。缺行、空值、坏价格、昨天的数据和失败批次不能当成停牌。
- 预先过滤停牌行的 Python provider 可实现可选方法 `get_daily_halted_symbols(day: date) -> set[str]`，必须以目标交易日的正式数据为依据。未实现时仍可正常同步；如有无法解释的缺行，自动任务报告不完整并停止环境分析，不以猜测放行。
- 自动任务缺少已选日线／因子能力时明确失败，不静默跨源回退。现有指数同步服务使用 TickFlow 的正式日线通道；该通道不可用时也不能用昨日指数或中性分伪装成当日就绪。
- 支持 `get_adj_factors(..., require_complete=True)` 的 provider 在自动任务中须传播上游取数错误；合法的无除权事件仍可返回空表。旧 provider 不需要新增该参数，但仍必须遵循错误与空数据分开的契约。
- 扶摇 dump 的进程缓存最多复用五分钟，此后重新核对 release；磁盘中相同 release 可复用。长期历史大文件保留原有按覆盖范围复用策略，近端数据由近期 dump 补充。
- Enriched 继续复用现有 generation／发布机制；环境、主线继续使用原持久化表。新增当日覆盖证据仅保留本轮股票集合，不增加数据副本、摘要校验或另一套行情缓存。

## 开关与独立任务

- 自动盘后任务固定包含 A 股、核心指数、环境与主线，不受手动同步范围和 `pipeline_regime_enabled` 开关影响；不改写这些历史偏好。该开关只控制数据页手动同步是否顺带计算环境。市场环境页“环境分析”仍是显式全量重算入口。
- ETF 和分钟历史继续尊重已有开关。源不支持的可选能力记录为跳过，不宣称完成了对应数据集的全量验收。
- 财务保留现有独立获取流程，不在 16:00 任务里增加每天全市场财报采集；报表发布并无统一的收盘完成时间。
- AI 复盘保留管理员归属、原独立时间、启用开关和费用边界，不因开启盘后数据同步而自动启用。周度研究仍按原设置触发。
- 普通分钟盘中增量、交易日历维护和盘前维表调度继续保持原职责；只读页面和 GET 接口不触发补采。

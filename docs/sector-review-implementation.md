# 板块复盘首版：实现与验证记录

记录日期：2026-10-25。设计基线：[sector-review-design.md](sector-review-design.md)，当前规则版本 `sector-review-v2`；第4—6节保留首版测量，第7节记录P2修订及复核。

已实现独立 `/sector-review` 页面与共用后端复盘服务。工程验证使用隔离正式行情样例，另做了本地历史数据只读采样。最新本地日期的正式行情仍不足；没有为展示榜单放宽正式数据或固定成员政策。历史结果属于当前分类名册回看，不是当时冻结的档案，也不表示预测能力已验证。

## 1. 页面与使用方式

侧栏新增「板块复盘」，菜单设置支持隐藏和排序，所有已登录用户均可读取。

| 视图 | 已实现内容 |
| --- | --- |
| 事件共振跟踪 | 人工指定T和观察S；T≤S≤T+3交易日；指数量价标签；T日共振三值条件；首次已观察／确定首次日期；连续走强天数及下限；T至T+3逐日证据；事前5／20／60日背景；固定事前成交额核心 |
| 调整逆势 | 5／10／20／60交易日窗口；单日和区间状态分开；绝对收益、相对净值收益；下跌日条件分母、完整性、小样本提示；窗口成员上涨比例和中位收益 |
| 共用控制 | 行业／概念、分类来源、行业层级、四核心指数、日期、最近完整日、只读刷新、名称搜索、数据不足筛选和排序 |
| 历史下钻 | 摘要包含逐日及核心证据；点击后分页读取全部历史成员；价格、额比和排除原因对应历史日期；当前股票预览明确写“查看当前行情” |
| 状态与版本 | 当前分类名册回看常显；请求／实际日期与形成日分列；覆盖、排除和比较政策独立展示；成员版本冲突返回409并要求刷新 |
| 窄屏 | 390px使用摘要卡片；详情表在容器内横向滚动，筛选和日期控制自动换行 |

URL保存视图、来源、层级、基准、日期和窗口。切换上下文使用不同查询键并传递取消信号；同一上下文刷新保留上次有效结果。已价格走强但缺成交额、市场对照或60日背景的板块仍可作为候选显示，并标明不足。

## 2. 数据与规则边界

- 分类标识为配置ID与字段生成的不透明ID，板块标识再包含层级和完整路径；概念在板块内去重，不将同名但不同来源／路径的板块合并。
- 证券样本先由维表的股票类型、交易所确认，再区分A／B股代码范围。不用最新ST状态或后续收益剔除历史成员。
- 成员形成日在T−1，或逆势窗口首日前一交易日。需21个连续交易日有效正式前复权收盘、20日正式成交额且均额大于零。仅60日背景不足不会改变形成名单。
- 完整正式行情必须无快照时间戳，并通过OHLC、成交量额和日期检查；前复权收盘还须与同日原始收盘依据一致。价格与成交额独立校验：金额缺失不清空仍有效的价格走强证据，价格缺失也不清空仍有效的金额事实，但完整性保持不足。15:30快照不会被当作正式日线。旧schema无 `quote_ts` 列沿标准扫描器兼容。
- 形成后固定名单：缺失不补零、不删成员重新归一。收益、成交额、市场广度和份额各自检查完整性，市场对照缺失不清空仍完整的板块自身指标。
- 板块为固定名单、每日等权重置的理论观察序列。区间收益复合；RS按 `(1+板块收益)/(1+基准收益)-1`；API比例均为小数制，超额差展示为百分点。
- 事件金额基线固定T前20日；逆势日证据使用各日此前20日。均排除评价当日，不使用成交量代替成交额，不称作净流入。
- 下跌日统计只以同窗口基准下跌日为条件分母；基准缺日则总数未知。单日或区间“逆势上涨”“相对抗跌”按互斥规则分类。
- ETF观察篮子尚未配置，独立返回 `unconfigured`；不自动猜选产品，不阻断股票与指数结果。篮子配置、定向补采和事件自动发现留在P2。
- 没有新增盘后步骤、采集任务、通知、AI联动或归档；原始研究材料和环境配置不变。

只读分类加载器不触发旧配置迁移；仅有旧 `ext_configs.json`、尚无独立配置目录时不自动转换，页面提示分类不可用。既有配置维护入口的迁移行为不变。

## 3. 实现与接口

| 位置 | 职责 |
| --- | --- |
| `backend/app/tickflow/sector_review_reader.py` | 本地窄列读取、正式性与资产校验、只读版本签名；不访问指标预热／实时快照 |
| `backend/app/services/sector_review_rules.py` | 成员形成、固定名单聚合、三值条件、收益与下跌日统计、首次响应和连续性 |
| `backend/app/services/sector_review.py` | 日期、分类、版本、单飞缓存、摘要、成员分页及缺失编排 |
| `backend/app/api/sector_review.py` | GET查询参数和响应模型；注册于核心main，沿用全局登录边界 |
| `frontend/src/pages/SectorReview.tsx` | URL状态、筛选、两个视图、桌面表格和窄屏卡片 |
| `frontend/src/components/sector-review/` | 历史证据、成员下钻和显示格式 |

| GET接口 | 主要参数 |
| --- | --- |
| `/api/sector-review/availability` | 无；返回本地日历、来源／字段／支持层级、四指数、最近完整日、最近日期覆盖审计及ETF状态 |
| `/api/sector-review/event` | `kind`、`dimension_id`、`level`、`benchmark`、`event_date`、`view_as_of` |
| `/api/sector-review/countertrend` | `kind`、`dimension_id`、`level`、`benchmark`、`as_of`、`window` |
| `/api/sector-review/members` | 上述模式完整上下文、`mode`、`sector_id`、`snapshot_id`、`page`、`page_size`（最高100） |

非法窗口／来源／日期返回422；非交易日包含相邻交易日提示。日历覆盖外、发布中和行情不足返回业务不可用状态，明确请求的交易日不会静默回退。默认完整日搜索按60日批次向历史回查，不以最近分区日期代表正式完成。

摘要的 `status=ready/partial/unavailable` 与条件真假、比较成员下限分开。成员明细如果输入已经修订，返回409，前端保留摘要并提供刷新。

## 4. 缓存与性能

后端有界缓存最多8份结果、TTL 300秒；availability最多4份、TTL 30秒。同键并发合并计算。每次查询先核对文件签名及已有发布标记，再使用缓存；构建前后复核版本，变更时丢弃并有限重试。日历和分类在解析前后也核对，GET不创建generation标记。

键覆盖数据目录、模式、T／S或D／W、基准、分类／层级、成员政策、规则、股票／指数／ETF文件、日历和分类版本。旧库用文件签名并明示版本保障较弱。前端日线／enriched、分类、日历和配置更新失效 `sector-review`；实时 `quotes_updated` 不重算历史。collector日历成功持久化后发布 `calendar` 数据更新通知，读取路径仍只读。跨进程修订通过文件／发布版本被下一次读取识别。

规模脚本：从backend运行 `uv run --frozen python scripts/benchmark_sector_review.py`。脚本只创建临时合成数据，退出清理，不读取用户运行目录。

2026-10-25测量环境为macOS arm64、Polars 14线程；6000只股票、400概念、100交易日，每只股票重叠12个概念，平均180成员／概念。以下为服务计算时间，**不含HTTP序列化、传输和浏览器渲染**。

| 模式 | 首次计算 | 缓存计算 | 摘要JSON大小 | 冷读取 |
| --- | --- | --- | --- | --- |
| 事件T至T+3 | 0.589秒 | 0.022秒 | 4,037,821字节 | 股票价格1次批量；内部原始股票1次、指数1次 |
| 逆势60日 | 0.642秒 | 0.029秒 | 1,582,411字节 | 同上 |

缓存命中不再读取行情内容，仅核对版本。两种模式连续执行的进程峰值RSS约789.5MiB，包含合成数据准备和两份结果缓存。重叠概念按10个日期分批聚合，将同规模临时联结峰值从约2GiB降低；没有按板块重复读取历史。不同参数大量并发及生产服务器硬件尚未压测，不能将本机单进程数值当作生产容量承诺。

## 5. 本地数据审计与实际回看

此次读取库存：股票与指数日线各248个日期分区（2025-10-10至2026-10-19），日历2025-10-13至2026-10-19，共247个确认交易日；独立ETF日线为空。维表可识别5887只A股，分类为31个一级行业、388个概念。

最近两日股票记录分别5567、5564条，指数各9条，均有非空快照时间戳。全历史原始股票1,358,936条，其中1,325,556条无快照时间戳；指数144,706条，其中144,652条无快照时间戳。**无时间戳只是正式性的必要输入之一，不能将这些数量直接等同完整验收通过。**

全本地日期回查未找到证券维表范围和四核心指数均完整的默认正式日，因此「返回最近完整日」禁用；可手工选择有正式数据的历史日期。availability冷审计约1.46秒。

| 2026-10-09 | 事件 | 31 | 8 | 5516 |
| 2026-10-09 | 逆势20日 | 16 | 0 | 5509 |
| 2026-09-24 | 事件 | 30 | 0 | 5518 |

| 2026-08-28 | 事件 | 28 | 0 | 5506 |

上述冷计算约0.26—0.30秒。另核对2026-10-09从S=T推进到实际T+3（2026-10-14），31个行业的T日证据完全不变，并成功分页读取历史成员。

2026-10-19事件成员形成中，5526只因事前包含快照、361只因历史缺行排除，形成市场集合为空；31行业／388概念均不可比较。逆势20日虽可形成5511只市场成员，但窗口后段正式行情不足，388概念的区间相对收益仍不可评估。页面保留原因，不能据此断言当天没有方向。

历史辅助证据完整覆盖偏低，是严格固定成员政策的实际限制。本轮未更改停牌、缺失或覆盖阈值；下一步应先核对正式日线和维表覆盖，再依据独立设计决定是否修订缺失政策，不可临时放宽分母。

## 7. 四项P2缺陷修订（2026-10-25）

四项均由隔离回归复现。修复前，新后端用例有7个参数组合失败，新增页面用例2项失败；其余3个后端组合用于保护空状态兼容和历史成员范围。

| 问题 | 根因与修订 |
| --- | --- |
| 缺基准成交额仍显示完整 | 每日完整性原先只检查板块辅助字段和基准收益。现在同时检查基准成交额与20日额比；当日金额或前20日基线缺失均为部分证据，行 `data_complete=false`，价格走强仍可保留 |
| 摘要与成员窗口收益不一致 | 摘要原来独立使用起止价格，明细使用每日连续收益。现在二者共用批量 `window_returns`，任一日缺价则成员收益不可算；原形成名单及分母不变，计数下降时上涨比例和中位收益为空，补齐后恢复 |
| 退市标的阻断最近完整日 | 维表读取原先丢弃 `is_current`。现在保留该字段，仅完整日验收排除明确的false，缺省和null继续严格验收。历史形成、市场比较及成员下钻仍保留有合格历史行情的非当前标的，不沿当前状态回溯删除 |
| 切换来源后层级与请求不符 | 页面原来从URL直接读取层级，换源只更新ID。现在按目标来源支持层级校正有效值，并原子更新URL；旧URL含不支持的层级时，首次请求前也完成校正 |

完整性、成员有效性政策修订后升级为 `sector-review-v2`，摘要与availability缓存均包含规则版本；新明细不会接到旧版摘要上。没有更改收益阈值、形成名单政策或盘后执行顺序。

修复后，板块复盘、盘后股票池、本地读取、缓存及schema相关测试61项通过，页面测试9项通过。新增后端10个参数组合、页面2项；原有隔离数据和用户工作区修改均保留。
